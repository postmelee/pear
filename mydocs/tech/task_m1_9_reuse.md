## Standard/system implementation choices

| Boundary | Implementation used | Why no additional package was adopted |
|---|---|---|
| Cooperative file locking | Installed Rust 1.94.1 `File::try_lock`, `try_lock_shared`, `unlock` | Actual contention, shared/exclusive behavior, release and arbitrary writer controls pass. A crate cannot turn advisory locks into ownership/generation proof |
| Disposable test roots | Python `tempfile.TemporaryDirectory` | Existing platform API; no custom random naming/cleanup framework |
| Retained staging directory | Darwin `mkdtempat_np` beneath a borrowed parent descriptor, fixed template | Native mode 0700/uniqueness/parent refusal tests pass; caller retains the returned name and owns later publication/cleanup |
| Streaming digest | System CommonCrypto `CC_SHA256_Init/Update/Final`, fixed 1 MiB buffer, `pread` | No new hash algorithm/library or handwritten SHA context ABI. Native empty/abc/multichunk, bounds/error and preserved-offset controls pass |
| Descriptor lifetime | Rust borrowed `AsFd` and standard `File`; existing pinned libc | No parallel FD or syscall abstraction. Actual at-use/immutable admission remains Stage 2 |

CommonCrypto deprecation declarations in the current SDK are locally suppressed for this existing system API boundary; ordinary C warnings remain errors. This does not make an SDK/OS deployment claim beyond the recorded host. Rust and Apple system libraries remain external tool/host inputs, not bundled copies.

## Stage 4 implementation update — October 9, 2026

State preparation extends the existing descriptor traversal, standard file locks and Stage 2 staged-file publication. `mkdirat`, no-follow opens, sync and the pinned libc `renameatx_np(RENAME_EXCL)` publish one new private context without replacing an existing directory. No installer, database, migration/copy framework or additional dependency was introduced. Existing partial staging remains unselected. The reviewed Whisky bottle-copy/rollback and registry patterns remain scenario references only; direct Swift code adoption is still none.

Each explicit lower-case context ID represents a caller-selected game/library instance. Closed local metadata binds its store/App ID, runtime compatibility family, exact profile and full cache identity, immutable selection snapshot, roots, and directory/lease device/inode identities. An exclusive context lease and one canonical in-prefix lease are retained through mutation or launch cleanup. Root/lock replacements, aliases and changed cache identity refuse at use. Immutable selection is retained per context, allowing explicit selection of an older clean context without applying a newer global selection to its old prefix. This local metadata is not another public profile format.

Version 2 executes only the approved boolean `fixture_flag` at `prefix/config/options.json`. The existing encoder/parser and descriptor-relative atomic file publication preserve unrelated setting keys; saves are not rewritten. Version 1 operations and unsupported v2 paths/keys remain refused. Launch verifies prepared settings and supplies manager-owned work/root FDs and WINEPREFIX after clearing the inherited environment. No manager branch inspects a fixture App ID. The two full v2 profiles use different App IDs, arguments, setting values, prefixes and saves. A small original C companion independently reads those values, preserves prior save bytes, emits a separate original-shape identity trace, and provides two compiled version markers for previous-runtime recovery tests.

`prepare` creates or re-prepares an exact compatible clean context under its leases; interrupted mutation leaves it dirty. `status` distinguishes prepared, clean, incomplete and busy without trusting a recorded PID. `recover --new-context` allocates fresh data without copying/deleting old saves; `recover --context-id` validates an explicitly selected previous compatible context, which is then supplied to `launch --context-id`. Dirty or incompatible contexts are never automatically cleared or migrated. Compatibility is deliberately conservative: exact prepared request/profile/cache identities must match.

Additional required regressions exposed a Darwin exit-query race inherited from the earlier lifecycle core: `proc_pidinfo` can stop returning the process identity before WNOWAIT reports its exit. The supervisor now retains its reservation and retries the same identity/exit proofs within the existing cleanup deadline before signaling the group. Numeric identity-query errors are available through the existing native wrapper; the original pipe-fault assertions remain unchanged apart from diagnostic text. Both fault positions passed 30 additional repetitions after correction. This is correctness evidence, not a timing/performance claim.

The original 58 source inputs and ten history records remain byte-identical. Stage 4's report separately records current tests, one conservative media-identification refusal during concurrent image lifecycle activity, the isolated-media final rerun, exact binary/input identities and preservation inventories.
