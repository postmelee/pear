### Approved Stage 3 amendment: native PE code publication

**Approval recorded:** on September 29, 2026, the requester explicitly approved this amendment and instructed implementation to proceed in this thread. **Why the plan needs expansion.** The measured operating system rejects both existing unsigned PE mapping paths. A native JIT primitive can execute fixed code, preserve ordinary writable data between executable subranges, and retain per-thread code-write protection. That does not resolve Wine's loader contracts. A shared process has one JIT allocation under Apple's documented Hardened Runtime model. Allocating it independently for Wine would conflict with a later FEX allocator. Wine also performs some relocation and executable-stub writes from PE code; that code cannot remain executable while the same thread places its entire JIT region in write mode. Image lifetime, ownership and native publication must therefore be designed together. [Apple JIT guidance](https://developer.apple.com/documentation/apple-silicon/porting-just-in-time-compilers-to-apple-silicon)

The repository requires clarification when work could conflict with existing work: "Ask first if scope is unclear or conflicts with other work." The explicit approval authorizes the bounded Wine implementation below; #5/#6 translator implementation and Stage 4's mutable-code/signal qualification still require their own approved work.

#### Implementation work and ownership

1. **Establish the allocation contract before porting Wine.** Specify arena ownership, upper bounds, address constraints, supported image alignment, code/data classification and bookkeeping. Select an aligned owned interior deterministically; do not retry until ASLR produces a favorable address. Define how later FEX can request code space through the same owner without implementing or claiming FEX now. Reject fixed/low-address requirements that the allocator cannot satisfy. Measure reservation size from the owned bootstrap image closure with an explicit limit, rather than reserving an unexplained large range. Before modifying Wine integration, require a standalone native layout/lifecycle prototype to pass 4 KiB code/data separation, two simultaneous slots, partial-failure rollback, exhaustion and retirement/reuse with differing compatible image layouts while preserving remaining JIT authorization. Specify immutable backing-class constraints and fragmentation bounds; explicitly reject incompatible reuse. If those gates fail, review the design before the large port.
2. **Load and relocate within signed native code.** Add a Wine-scoped C implementation through a new ordered patch such as `0003e-darwin-pe-publication.patch`. Keep code pages in the authorized JIT allocation and map headers/IAT/writable data to owned ordinary non-executable memory. Preserve PE RVAs, section zero fill and declared protection boundaries. Check file reads, every range/overflow and every supported relocation before writes. Relocate from the original PE base to the actual slot; update only the mapped header after success. Preserve the server's global address preference and informational `STATUS_IMAGE_NOT_AT_BASE`. Prevent a second PE-side relocation pass from writing executable pages.
3. **Publish with explicit state and authorization.** Validate the actual loader's matching profile and exact claims, adding only the documented public `allow-jit` entitlement where the selected implementation needs it. Select that policy from applicable platform documentation and actual matched controls; do not infer necessity from these preliminary trials. Keep Hardened Runtime, library validation and 4 KiB signatures. Keep the bounded writer in native host mode, close the writer window on every recoverable error, invalidate the instruction cache, and return to PE only in execution mode. Pre-validate inputs outside the writer window; an unexpected fatal fault ends that owned process rather than resuming with writable code. Preserve the existing x18 boundary checks.
4. **Define teardown and unsupported behavior.** Model reserved, preparing, published, failed and retired slots. Prevent accidental replacement of JIT backing by generic Wine unmap paths. Require retirement and quiescence under Wine module references and Pear-owned entry/callback ownership before a slot can be reused. Raw address recycling does not make arbitrary dangling guest pointers safe; document that limit explicitly. Require safe unload/reload and allocation-failure behavior before qualification; a monotonically leaking arena is not an accepted final design. Reject unsupported shared executable images, mixed writable/executable pages, malformed relocations and guest-generated executable stubs explicitly. Do not silently substitute a fake API or relax protections. #### Upstream reuse decision for the approved amendment

The implementation starts from the pinned Wine view tree, page-protection metadata and `create_view`/`register_view`/`delete_view` lifecycle.
