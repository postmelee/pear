# Security policy

## Supported versions

Pear is under development and has no qualified public release or security support
window yet. Report findings against the current development revision, identifying
the affected Pear/runtime version. Do not assume an older candidate is supported.

## Report privately

The selected channel is GitHub private vulnerability reporting: use **Security →
Advisories → Report a vulnerability** in the [Pear repository](https://github.com/postmelee/pear/security/advisories).
Include the affected revision, impact, reproducible steps and a minimal sanitized
example. Keep game payloads, credentials, signed-in prefixes and private keys out
of attachments. Do not post vulnerability details in public Issues or Discussions.

**Availability:** maintainers must enable GitHub private vulnerability reporting
when opening the repository. If **Report a vulnerability** is unavailable,
withhold sensitive details; an existing authorized collaborator may ask the
maintainer to arrange a private route without describing the exploit publicly.
No public email address or response-time commitment is established.

Maintainers assess scope, coordinate a fix and disclosure with the reporter, and
preserve attribution with consent. Reports concerning upstream components may
need coordination with their maintainers under their own policies. Successful
code signing/notarization alone does not establish runtime security or qualification.

See [GitHub's private reporting documentation](https://docs.github.com/en/code-security/how-tos/report-and-fix-vulnerabilities/configure-vulnerability-reporting/configure-for-a-repository)
and the [public-opening checklist](community.md#public-opening-checklist-for-maintainers).
